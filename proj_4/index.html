Project 4A: Image Warping and Mosaicing

In this project I took sets of photos by rotating my camera around a fixed point (just rotating the camera around while I stood stationary), computed the homographies between them from hand-clicked correspondences, wrote my own inverse warping with nearest neighbor and bilinear interpolation, rectified images of rectangular objects, and blended image pairs into mosaics using weighted averaging.

A.1: Shoot the Pictures

I shot each set by standing in one spot and then rotating the camera to the left between shots, keeping the center of projection fixed. This way the images are related by projective transformation, allowing us to combine them into a mosaic. Each pair overlap a great bit so that there are shared features between the two photos.

A.2: Recover Homographies

A homography will map a point in one image (x, y) to another point (x′, y′) in another through a 3x3 matrix H. Writing the point as (x, y, 1) and multiplying by H gives (wx′, wy′, w), and dividing by w gives the final point. Since H has 9 entries and does not get effected by scaling, I fixed the bottom-right entry to 1, leaving 8 unknowns h1 to h8.

Multiplying out the division and rearranging makes the equations linear in the unknowns. Each correspondence gives two equations: 

x·h1 + y·h2 + h3 − x·x′·h7 − y·x′·h8 = x′
x·h4 + y·h5 + h6 − x·y′·h7 − y·y′·h8 = y′

For all n pairs of points, I combined the equations into a system Ah = b, where A is a 2n × 8 matrix and b contains the x′ and y′ coordinates. Although 4 points are enough to solve the system, small errors from selecting the points can affect the result. To make the homography more accurate, I used more than 4 points and solved the system using least squares with the normal equations. 

h = (AᵀA)⁻¹ Aᵀ b

Finally, I set the last value to 1 and reshaped the 9 values into the homography matrix H. I used the correspondence tool to select matching points, near a certain identifiable feature like a hole in the barrel, or a corner of a bookcase/window.

A.3: Warp the Images

I implemented warpImageNearestNeighbor(im, H) and warpImageBilinear(im, H) using inverse warping. Forward warping/mapping (placing each input pixel through H) leaves gaps because the pixels will land at a fractional point and spread apart. Therefore I did inverse mapping, which places every pixel in the output through pixels land at fractional positions and spread apart. Instead, for every pixel in the output, it send it backwards through H⁻¹ to find where it came from in the original image. So every output pixel will get a value.

Both functions follow the same steps:

  1. Output size: The 4 corners of the input image are transformed using H. Since a homography keeps straight lines straight, the smallest bounding box containing the transformed corners determines the output size.
  2. Inverse mapping: For every pixel in the output image, H⁻¹ is applied and the result is divided by w to find the corresponding source location in the original image.
  3. Interpolation: The pixel color at the source location is calculated using one of the two interpolation methods described below.
  4. Empty pixels: If the source location falls outside the original image, the output pixel is left black.

Each integer coordinate represents the center of a pixel, so (0, 0) corresponds to the center of the first pixel.

  • Nearest neighbor: The source location is rounded to the nearest pixel, and its color is copied to the output image.
  • Bilinear: The 4 pixels surrounding the source location are used to calculate the output color. With dx and dy representing the fractional distances from the top-left pixel, the top two pixels are blended using dx, followed by the bottom two pixels. These two results are then blended using dy, giving closer pixels more weight.

Rectification

To test the warping, I rectified photos of rectangular objects taken at an angle. Since there's only one image, I clicked the 4 corners of the object as im1_pts, and defined im2_pts by hand as a rectangle with the object's estimated proportions. Computing H from these and warping changes the object as if seen straight and not from the side.

Neighbor vs Bilinear

Nearest neighbor is faster, since it reads one pixel per output pixel. Bilinear reads four and does the blending math, so it takes longer. However, bilinear gives a smoother result compared to nearest neighbor, which produces a more jagged result, especially around text and anything with straight lines. Bilinear makes it more blurry due to the smoothing.

A.4: Blend the Images into a Mosaic

Procedure

  1. Homography: For each pair of images, H is computed using the clicked correspondences from A.2 to map the side image into the center image's coordinate system.
  2. Warping: The center image remains unchanged, while the side image is transformed using bilinear inverse warping. The warping function also returns the offset of the warped image's top-left corner.
  3. Output size: The smallest output that fits both the center image at (0, 0) and the warped side image at its offset is calculated using the minimum and maximum coordinates of their edges.
  4. Weights: Each image is assigned a weight map with a value of 1 at the center that decreases linearly to 0 at the edges. The side image's weight map is warped using the same H to keep the weights aligned with the image pixels.
  5. Blending: Instead of having one image overwrite the other and create a visible seam, weighted averaging is used to combine the images. For each pixel on the output, the pixel colors are multiplied by their corresponding weights and added together. The result is divided by the sum of the weights. In overlapping regions, pixels closer to the center of an image receive more weight, creating a smoother transition. Regions covered by only one image retain that image's color, while uncovered pixels remain black.
mosaic = (color₁·w₁ + color₂·w₂) / (w₁ + w₂)
